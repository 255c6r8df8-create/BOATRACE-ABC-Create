# 閉じるたび一覧が消える問題の保存先修正

ユーザーはホーム画面版でJSON復元後にも、閉じるたび一覧が表示されないと報告。iOSの実端末原因は未特定。従来はクロスオリジン埋込み側のIndexedDB/localStorageのみで、既存アプリ本体のkeep-hostは旧resultsオリジンだけを受け付け、固定ベースWorkerとは未接続だった。

新たに固定ベース専用の本体保存を追加。アプリ本体のoriginでBOAT_LAB_FIXED_BASE_HOST_V1に原本を保持し、保存後の再読込が一致して初めて保存成功を返信。埋込み側は本体の保存を読み出し、正常な現行候補・選択表示を再計算する。旧原本と購入記録には手を加えない。送信元originと実際のcreator/results iframeのwindowを双方照合する。

viewerは本体保存・正常な端末保存・予備保存から読み、1件の検証失敗で全件を止めない。復元時に予備保存の成否も明示。creatorの固定ベース保存でも本体へ書き込む。

重要：Worker配信だけでは本体の受信機能は追加されない。既存boatrace-abc-app PagesはNo Git connection/手動ZIP配信で、現在この環境にPagesの配信権限はない。完成済みボート研究_保存修正_20261113.zipを既存Pagesプロジェクトへ反映する操作が必要。新規プロジェクト作成・保存データ消去・旧管理分析の変更はしない。

ZIP：16ファイル、5150305bytes、SHA256 f10956c794566ade757f49f9cc3a43c9325c3fcfbb142ea4141a0d1f2e611627。受領外枠のindex.htmlとkeep-host.jsだけ変更。

親本体の保存後読取・原本保持・二重保存防止・不正origin/source拒否・埋込み再生成後の読取を単体テスト。正常な別日原本を不正レコードが妨げないこととIndexedDB失敗時の予備保存読取もテスト。実iOSで終了・再起動後の検証は未実施。双方の保存領域が既に消えている場合、以前未受領の原本を自動復元できるとは説明しない。
