# 保存日が空でオプションなしになる問題への復旧対応

ユーザーの実機では本日のレースの開催日欄にオプションなし。現在のreaderが0件として扱っていることは確認できるが、既存データが別保存領域へ隔離されたのか、Safariが消去したのか、他の保存場所なのかは特定できていない。コードにデータ削除処理はないことだけで「データは消えていない」と断定しない。

保存日を明示的に初期選択する。0件なら原因不明の空欄でなく0件と復元方法を表示。保存JSONをファイル入力で検証して復元する。原本の入力・成績・保存時刻・旧モデルは保持し、既存レコードを上書きしない。同じ入力・成績・モデルの再取込は重複追加しない。表示と参考集計は確定ルールで再判定。

今後の固定ベース保存時には、IndexedDBに加えlocalStorageへ最新1件の予備コピーを作成する。予備保存失敗は主保存成功と区別して表示。読み込み0件の場合のみ、同じ保存領域の予備コピーを検証して表示する。ブラウザ全領域削除や異なる保存コンテキストをまたいだ自動復旧が保証されるわけではない。

旧JSONの読取専用再判定では、原本保存が締切前のときに限り、既に配布されていた同一ハッシュの公式期別データで不足欄を再構成する。原本を書き換えず、締切前の購入予想として扱わない。

テスト：旧原本検証、予備コピーの往復、破損・容量不足時の扱い、保存0件表示、保存日初期選択、原本JSON取込、重複取込防止、既存原本保持。公開後にユーザー端末上の復元は別途必要。今回こちらが保存したルール/コードのZIPと、ユーザー端末に保存した当日データは別である。
